# Data, Packets, and the Rules of the Internet

The internet is not one machine, and no single company owns or runs it. What holds it together is agreement on rules: a set of protocols that every device follows so that data from one side of the planet can reach the other. The two headline rules are the Internet Protocol, or IP, and the Transmission Control Protocol, or TCP. Together people call them TCP/IP, and almost everything you do online rides on top of them.

When you send a file, a message, or a video, your computer does not ship the whole thing as one giant blob. It splits the data into small pieces called packets. Each packet carries a payload, which is a slice of your data, plus a header that records where it came from, where it is going, and where it fits in the sequence. Think of a packet as an envelope with a return address, a destination, and a page number written on it.

Packets are useful because the internet is a shared, messy place. If the network sent a whole file and one link failed, you would have to start over. With packets, each piece can take its own route. Routers, the machines that sit at the junctions of the network, look at the destination address in each packet's header and forward it to the next hop along a path they believe is good. Different packets from the same file can travel by different paths and arrive out of order, duplicated, or not at all.

That is where TCP earns its keep. IP is a best-effort delivery service: it addresses and routes packets but promises nothing. TCP sits on top of IP and adds the guarantees people expect. It numbers the packets, reassembles them in the correct order at the destination, acknowledges the ones that arrived, and asks for retransmission of anything missing. If a packet is lost, TCP notices and sends it again, so the file you receive is complete and in order even though the underlying network is unreliable.

Every device on the internet also needs an address. An IP address is a number that identifies a machine, roughly like a postal address for data. IPv4 addresses look like 192.168.1.10 and are running out, so the newer IPv6 uses much longer addresses to provide essentially unlimited room. Addresses are not the whole story, though, because one machine can run many services at once. Ports solve that: a port number says which program on the machine should receive the packet. Web traffic traditionally uses port 80 for HTTP and port 443 for HTTPS, while email uses different ports.

One more safety valve matters. Every packet carries a small counter called the time to live, or TTL. Each router that handles the packet lowers the counter by one, and when it reaches zero the packet is thrown away. Without TTL, a routing mistake could send a packet around a loop forever and the network would slowly fill with ghosts. TTL quietly guarantees that even broken packets eventually die.

Put together, these rules explain the strange shape of the internet: no central controller, no guaranteed path, and yet a file arrives intact. The system works because unreliable pieces are combined with careful bookkeeping. IP handles the messy job of moving packets, TCP handles the tidy job of making them add up to something you can trust, and TTL keeps the whole dance from going on forever.
